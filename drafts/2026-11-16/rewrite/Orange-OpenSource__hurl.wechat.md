# 先定边界，再谈 hurl

> 先弄清 hurl 管什么，再决定用不用。

同样的活儿换个做法，省下来的往往不是时间，是反复确认的功夫。今天说个能自己试试的小工具。

## 它是什么

hurl 是 GitHub 上的一个开源项目，用 Rust 写，19324 人收藏，采用 Apache-2.0 协议。作者自己写的介绍放在项目页面，点进去能看见。

## 先记这几点

- 不用 delay 的实现
- html / txt / json 格式支持

## 怎么用

项目说明里没给能复制的安装命令，它更像一份要照着写的约定。说明里分了几块，去项目页面按顺序看就行。
